# Push通知購読APIの保護設計（#360）

## 目的

認証なしで公開している /api/push/subscribe と /api/push/unsubscribe について、入力値によるKV容量圧迫と短時間の大量書き込みを抑止する。

## 設計

- endpoint は2,048文字、p256dh と auth は各256文字を上限とする。既存の許可ホスト・HTTPS検証は維持する。
- リクエスト本文は8KiBまでに制限し、超過・JSON不正は従来どおり400を返す。
- Cloudflareが付与する CF-Connecting-IP を優先して、クライアント単位で1分10回の簡易レート制限を行う。ローカル/プロキシ環境では X-Forwarded-For をフォールバックとして使う。超過時は429と Retry-After: 60 を返す。
- 購読レコードには90日間の expirationTtl を付ける。購読更新でTTLは延長され、失効レコードが無期限に残らない。

レート制限はWorkersインスタンス内のメモリを使う簡易防御であり、インスタンスをまたぐ厳密な上限ではない。将来、より強い制御が必要になった場合はCloudflare Rate Limiting bindingへ置き換える余地を残す。入力上限とTTLは、単一インスタンスに依存せず適用される。

## 運用上の判断

購読APIはログイン不要であるため、厳しい制限を設定して正規ユーザーを阻害しないよう、1分10回を初期値とする。TTLはWeb Push購読の定期更新を前提に90日とし、通知送信時の410/404削除経路と併用する。
